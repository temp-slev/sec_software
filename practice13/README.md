В namespace `practice13` развёрнут отдельный FastAPI-сервис; метрики собираются общим
Prometheus-стеком из Практики 12. Grafana автоматически загружает собственный дашборд,
правило оповещения и email contact point. Локальный SMTP-сервер Mailpit принимает
настоящие письма Grafana без внешнего почтового аккаунта.

## Результаты

- Источник Prometheus настроен как Default, проверка связи возвращает health=OK.
- Собственный дашборд содержит 8 панелей: RPS, процент ошибок, p50/p95/p99,
  запросы по подам, custom counter, CPU, память и количество запросов по статусам.
  Проверен каждый PromQL-запрос панели, данные возвращаются.
- **Задание 1:** `my_custom_counter` увеличивается на `/`, в Prometheus публикуется как
  `my_custom_counter_total`; на дашборде есть отдельная панель.
- **Задание 2:** правило Grafana `FastAPI 5xx over 5 percent` вычисляет долю ответов 5xx
  за последние 5 минут, порог >5%, проверка каждые 30 секунд, `for: 30s`.
  Во время нагрузки измерено около **50%** ошибок. Состояние правила — firing;
  Grafana отправила email, Mailpit получил его на `alerts@example.test`.
  Тема письма: `[FIRING:1] FastAPI 5xx over 5 percent Practice 13 (13 warning)`.
- **Задание 3:** приложение масштабировано с одной реплики до двух (READY 2/2).
  В Prometheus и панелях присутствуют метрики обеих реплик с разными метками `pod`.

Протокол полного результата — `logs/grafana-check.log`; письмо и состояние правила —
`logs/email-evidence.json`, `logs/alert-state.json`; масштабирование — `logs/scaling.log`.
`/fail` создаёт контролируемые HTTP 500 для проверки оповещения. Канал проверен именно
срабатыванием правила под нагрузкой, а не кнопкой Test contact point.

## Особенности конфигурации

- Kubernetes Docker Desktop используется вместо Minikube. Инструментация включается
  переменной `ENABLE_METRICS=true`; `/health` и `/metrics` исключены из подсчёта запросов.
- Один Helm-релиз Prometheus/Grafana обслуживает практики 12 и 13. Запросы разделены по
  `namespace`, поэтому метрики разных работ не смешиваются.
- Вместо готового стороннего дашборда создан собственный, согласованный с реальными
  метриками приложения. Он хранится в репозитории и загружается автоматически.
- Числитель процента ошибок использует `or vector(0)`: отсутствие ошибок отображается
  как 0%, а не как отсутствие данных. В правиле пятиминутное окно задаётся `[5m]`;
  `for: 30s` — отдельное время подтверждения превышения.
- Панели используют `http_requests_total` и Histogram `http_request_duration_seconds_bucket`.
  Счётчик `my_custom_counter_total` показан по подам.
- Mailpit — локальная SMTP-доставка учебного стенда, без пересылки во внешние почтовые сети.

## Ответы на контрольные вопросы

1. **Источник данных.** Grafana обращается к HTTP API Prometheus по URL Service в кластере;
   источник типа Prometheus с UID `prometheus` задан provisioning-конфигурацией Helm-чарта.
2. **ServiceMonitor.** Позволяет оператору Prometheus автоматически обнаружить и опрашивать
   `/metrics` обоих подов через метки и именованный порт Service.
3. **Типы метрик.** Counter — накопительный счётчик, Gauge — текущее значение, Histogram —
   распределение по buckets, Summary — локально рассчитанные квантили и sum/count.
   Квантили Summary нельзя просто усреднить по нескольким репликам; Histogram позволяет
   агрегировать buckets перед вычислением квантили.
4. **Инструментация.** Middleware измеряет число, длительность и размеры запросов/ответов
   и публикует показатели в `/metrics`; группировка статусов задана как `2xx`, `5xx` и т. д.
5. **Дашборды.** Импорт поддерживает JSON или ID каталога Grafana. Готовые 17175/14573
   из методички требуют сверки имён метрик; здесь применён собственный JSON с проверенными
   запросами, чтобы избежать несоответствия версий библиотек.
6. **Среднее и p95.** Это разные величины. Средняя задержка за 5 минут:
   `sum(rate(http_request_duration_seconds_sum{namespace="practice13"}[5m])) /
   sum(rate(http_request_duration_seconds_count{namespace="practice13"}[5m]))`.
   p95: `histogram_quantile(0.95, sum by (le)
   (rate(http_request_duration_seconds_bucket{namespace="practice13"}[5m])))`.
7. **Защита /metrics.** Ограничить сетевой доступ, при необходимости настроить авторизацию
   scrape и TLS. В этом стенде приложение имеет ClusterIP, а локальный доступ сделан
   port-forward. Из метрик исключены probes и scrape; в labels не следует включать
   пароли, токены, персональные данные и неограниченные пользовательские значения.

После сохранения результатов проверочные поды остановлены, общий Helm-стек удалён
для освобождения ресурсов. Конфигурация и протоколы сохранены в репозитории.
