## Реализация

Локальное S3-совместимое хранилище MinIO и микросервис FastAPI развёртываются в Docker
Compose. Бакет `data-lake-bucket` и объект `sample.json` создаются отдельным сервисом
инициализации. Приложение подключается к MinIO через boto3; данные хранятся в томе
`minio_data` независимо от жизненного цикла контейнеров.

| Путь | Назначение |
|---|---|
| `app/main.py` | API для бакетов, объектов, загрузки, скачивания и агрегации JSON |
| `app/requirements.txt`, `Dockerfile` | зависимости и образ приложения, пользователь UID 10001 |
| `docker-compose.yml` | MinIO, инициализация бакета, FastAPI и постоянный том |
| `storage/Dockerfile` | сборка MinIO и mc из официальных исходников с проверкой коммита |
| `sample_data/sample.json` | исходный объект из задания |
| `verify.py` | интеграционная проверка API с реальным MinIO |
| `logs/` | протоколы выполненных проверок |

Порты на локальном хосте: **8009** — FastAPI, **9000** — S3 API, **9001** — MinIO Console.
Переменные `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` задают подключение;
`.env.example` содержит демонстрационные значения для локального учебного стенда.

## Контракт API

| Метод и путь | Результат |
|---|---|
| `GET /` | состояние сервиса |
| `GET /health` | проверка доступности бакета |
| `GET /buckets/` | список бакетов |
| `GET /objects/?prefix=&file_type=json` | список объектов с размером и датой; фильтрация по префиксу и расширению |
| `GET /objects/{key}` | JSON или текст объекта; для бинарного содержимого — HTTP 415 |
| `POST /upload/?key=...&content=...` | загрузка текстового содержимого, как в методичке |
| `GET /aggregate/` | сбор данных всех JSON-файлов; ошибочные JSON отмечаются отдельно |
| `GET /download/{key}` | потоковое скачивание как вложения с исходным именем |
| `POST /upload-file/?key=...` | multipart/form-data, поле `file`; S3 multipart upload для больших файлов |
| `GET /docs` | OpenAPI / Swagger UI |

Ключи могут содержать `/`, например `reports/sample.json`; файловых каталогов в S3 при этом
не создаётся. Неверный ключ возвращает 404, неверный формат параметра — 422, недоступность
хранилища — 503. Ответы скачивания поддерживают UTF-8 в имени через `filename*`.

## Выполнение этапов и заданий

1. MinIO хранит данные в постоянном Docker volume. Инициализатор `mc` создаёт бакет и
   копирует `sample.json`; повторный запуск допускает уже существующий бакет.
2. FastAPI реализует чтение бакетов, объектов, JSON и текста, загрузку содержимого.
3. Приложение запускается после успешного завершения инициализатора;
   инициализатор ожидает healthcheck MinIO.
4. Проверяются загрузка и чтение через API, список объектов, исходный файл и документация.
5. `/aggregate/` читает JSON-объекты и возвращает их содержимое вместе с именами.

**Задание 1.** `StreamingResponse` читает объект порциями по 64 КиБ и закрывает S3-поток
в `finally`. Заголовки `Content-Disposition: attachment` и `filename*` задают имя скачивания.

**Задание 2.** `file_type` фильтрует расширение на стороне сервиса, без учёта регистра;
принимаются `json`, `.json`, `txt`. Его можно сочетать с `prefix`.

**Задание 3.** `UploadFile` и `boto3.upload_fileobj`: порог multipart 5 МиБ, размер части
5 МиБ, до четырёх параллельных передач (`use_threads=True`). HTTP multipart/form-data и
S3 multipart upload — разные механизмы: первый передаёт файл в API, второй делит его
на части между boto3 и MinIO. Выполненная проверка передаёт файл размером 12 МиБ и
подтверждает три части через ETag, события S3 и совпадение SHA-256 после скачивания.
Необязательный прогресс-бар не добавлялся.

## Отличия от примера методички

- Готовые образы `minio/minio`, `minio/mc` недоступны из проверенных реестров; официальный
  архив бинарных файлов возвращает HTTP 410. Поэтому компоненты собираются из исходников:
  - [MinIO RELEASE.2025-04-22T22-12-26Z](https://github.com/minio/minio/tree/RELEASE.2025-04-22T22-12-26Z),
    коммит `0d7408fc9969caf07de6a8c3a84f9fbb10a6739e`;
  - [mc RELEASE.2025-04-16T18-13-26Z](https://github.com/minio/mc/tree/RELEASE.2025-04-16T18-13-26Z),
    коммит `b00526b153a31b36767991a4f5ce2cced435ee8e`.
  Сборка проверяет hash коммита; лицензия исходного компонента включена в его образ.
  Используются исторические версии для воспроизводимости учебного стенда.
- Инициализатор останавливается при ошибке, вместо безусловного `exit 0` из примера.
- boto3 синхронный, поэтому эндпоинты объявлены обычными `def` и выполняются FastAPI
  в пуле потоков, не блокируя цикл событий.
- Список объектов обходит все страницы S3, включая бакеты с более чем 1000 объектами.
- Убрано bind-монтирование, которое перекрывало бы путь `app.main` внутри образа.
- Приложение опубликовано на порту 8009, чтобы не конфликтовать с другими работами.
- Файл скачивания передаётся потоком, бинарный объект не декодируется как UTF-8.

## Ответы на контрольные вопросы

1. **DataLake и DataWarehouse.** DataLake сохраняет исходные данные разных форматов;
   схема часто применяется при чтении (schema-on-read). DataWarehouse хранит подготовленные
   структурированные данные с моделью для аналитических запросов (schema-on-write).
   S3 — объектное хранилище и возможная основа DataLake; само по себе оно не выполняет
   SQL-аналитику и не является полноценным DataWarehouse.
2. **boto3 и S3 API.** boto3 — Python SDK для AWS-совместимых сервисов. Использованы
   `list_buckets`, `head_bucket`, `list_objects_v2` с paginator, `get_object`, `put_object`,
   `upload_fileobj`, `head_object`. Клиент подписывает запросы и обрабатывает протокол S3.
3. **MinIO.** Позволяет локально проверить S3-операции без аккаунта AWS и оплаты облака.
   S3-совместимость означает поддержку соответствующих операций API и подписей запросов;
   она не гарантирует полного совпадения всех дополнительных возможностей AWS.
4. **Ожидание запуска.** Healthcheck проверяет готовность MinIO; `depends_on` с условием
   `service_healthy` запускает инициализатор после готовности, а
   `service_completed_successfully` запускает приложение после создания бакета.
5. **Объектное хранилище.** Подходит для большого числа файлов, независимого масштабирования,
   обращения по HTTP API и разделения вычислений и хранения. Объект адресуется ключом в
   бакете, поддерживает метаданные. Оно не предоставляет обычные POSIX-операции и не является
   прямой заменой файловой системе для произвольного приложения.
